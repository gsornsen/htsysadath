Q·01 18 How do you decide what to delegate to an agent versus do yourself? EngineerPMDesignerNew to agents

I delegate anything mechanical or well-specified — extraction, summarizing a known-shape doc, formatting — and keep judgment calls for myself: what the talk argues, which finding matters, how a persona would react. The rule I actually use is model routing by task shape, not by how much I trust the tool. If I can write the acceptance test in one line, an agent runs it. If I can't say what "done" looks like yet, I do it myself first, then hand off the repeatable part once the shape is clear.

Q·02 9 How do you make sure results are reproducible when the model's own output is not deterministic? EngineerNew to agents

Every model call gets cached as a replay fixture keyed by a hash of the pass, prompt, persona and inputs. Replay mode — the default — never calls a model; a missing fixture is a hard error, not a silent live call. Every deterministic pass is a pure function of its inputs: stable ids, sorted output, no timestamps, no randomness. Two replay runs of the pipeline are supposed to produce a byte-identical page, checked by comparing hashes of the rendered output.

Q·03 7.5 What is your process for keeping private data out of a public repo? PMDesigner

Findings get paraphrased before they're written down, never pasted verbatim, and attributed to a session id and date instead of a name. Before any commit I grep the staged diff for the shapes that tend to leak — API keys, emails, private IPs, local home paths — and treat a hit as a blocker, not a warning. The corpus behind this demo stores only a sha256 of anything private, never its content, so the public repo never sees the source material directly.

Q·04 5 Where does this approach break down, or start costing more than it saves? Engineer

In my experience this breaks down fastest around shared state — a worktree that forked before a merge lands quietly diverges, and an agent working in it will confidently build on a stale assumption. The fix isn't more automation, it's a habit: check the fork point before trusting a branch. I don't have a clean measurement for how often this bites, just the one lesson logged after it did, so take this as my read on it rather than a proven rate.
