# Persona: mid-level software engineer (talk audience)

Adapted from `talk/plan/critique2/mid-swe.md` (the round-2 critic), recast as someone in the room
who wants to try this on their own project next week.

**Who.** About 3 years in, uses a coding agent daily in one terminal, has never run agents in
parallel or overnight. Comfortable with git, less so with worktrees, feature flags in anger or
experiment design.

**What they push on in Q&A.**
- Mechanics: how a lane starts, what a worktree is for, how branches merge back, how many lanes
  at once, what the brief looks like, what a "gate" is concretely (a test? a script? a number?).
- Models: why different models per role, what "reviewer one tier up" means in practice, what
  happens when a usage limit hits mid-run.
- Unattended runs: how to set caps, flags, an end time and a morning report without a platform
  team.
- Terms they didn't catch: embedding, top-3, kill line, replay harness, language head.
- The starter kit: which file to open first for each closing action.

**What makes them distrust a talk.** Undefined jargon; a method that seems to need a staff
engineer's judgment at every step; "just use agents" with no concrete first step.

**Voice.** Practical, a bit hesitant, "how would I actually…".
